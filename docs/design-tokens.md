## 1. 令牌提案

三条原则：

1. **不发明新色值** —— 能从两个项目现有取值里选到达标的那一个，就不新造。下表每个值都能在现有代码里找到出处。
2. **同名同义** —— 两个主题共用一套语义名，只是取值不同；不再出现 `--panel`/`--surface`、`--ok`/`--success`、`--err`/`--danger`、`--text-soft`/`--text-2` 这类"同义不同名"。
3. **深色主题取值零改动** —— login / admin 的观感保持原样（它已达标），只统一变量名。

现状的 `12.5 / 13.5 / 11.5` 是"看着调"的中间值。收敛成 6 档，**保留两个最高频值（12.5、13.5）不动**以减小观感位移：

## 2. 迁移方式（一次一页）

1. 每页**单独提交**，顺序 `login → index → admin`；两个项目各自独立提交、各自跑测试。
2. 每页只做三件事：① `:root` 补齐统一令牌；② 该页内的硬编码换成 `var(...)`；③ 按 §1.3 / §1.4 映射表收敛间距与字号。
3. **硬边界（不满足就不提交）**：
   - 不改任何 `id` / `class` 名 / 函数名 / DOM 结构 —— 既有静态断言与 3 份 Node 行为断言（login 17 项 / index 20 项 / admin 41 项）必须原样通过；
   - 不引任何外部资源（零 CDN 不变）；
   - 全量 pytest 全绿（当前 项目一 432 / 项目二 634）。
4. 目视验收：每页改完本地起服务看一眼（登录页三屏、工作台空/有会话、后台五个 tab），确认没有塌布局、没有对比度倒挂。

## 3. 待你拍板的三件事

### 3.1 深色主题的强调色

- **A（推荐）统一到靛蓝 family**：深色用 `#818cf8`（对 `#182031` 为 **5.46:1**，比现值 `#4c8dff` 的 5.09:1 更好），浅色 `#4f46e5`。两个项目从此是同一个品牌色。
- **B 保留现值** `#4c8dff`（深）+ `#4f46e5`（浅）：观感零变化，但"一个产品两个强调色"会作为已知取舍写进文档。

### 3.2 浅色主题的画布底色

项目一 `#F4F5F8` vs 项目二 `#eef1f8`：两者对比度之差 **1.037:1**，肉眼基本不可分辨。建议取项目二的 `#eef1f8`（它的 `--bg-grad` 渐变已围绕这个底色调过）。

### 3.3 圆角是否真的收敛

`9/10 → 8`、`14 → 12` 是本轮唯一的可见观感变化。要"零观感变化"就只统一命名、保留现值。

## 4. 明确不做的事

- 不引入 Tailwind / 任何 CSS 框架或预处理器（与"自包含、零 CDN"一致，也避免把样式构建变成新的依赖）。
- 不改布局结构（栅格、断点、DOM 层级）——只统一"值"，不重构"形"。
- 不改字体族（`--mono` 两个项目取值本就不同，属平台差异，保留）。
- 不加动效、不加装饰性渐变、不追求炫酷。
- 不动深色主题的取值（它已达标），只统一变量名。

## 附：这些数字怎么来的

- 颜色字面量 / 变量 / 取值分布：正则扫描 6 个页面的 `<style>` 块（不含 `<script>` 里的内联样式字符串，后者单独统计）。
- 对比度：WCAG 2.1 相对亮度公式 `(L1+0.05)/(L2+0.05)`。
- 每个提案值都标注了"出处"，且都验过对比度（见 §1.1 / §1.2 表格）。
- 结论可复算：审计与对比度都是脚本算出来的，不靠肉眼估计。
