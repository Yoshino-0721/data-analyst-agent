## 1. 令牌提案

三条原则：

1. **不发明新色值** —— 能从两个项目现有取值里选到达标的那一个，就不新造。下表每个值都能在现有代码里找到出处。
2. **同名同义** —— 两个主题共用一套语义名，只是取值不同；不再出现 `--panel`/`--surface`、`--ok`/`--success`、`--err`/`--danger`、`--text-soft`/`--text-2` 这类"同义不同名"。
3. **深色主题取值零改动** —— login / admin 的观感保持原样（它已达标），只统一变量名。

## 2. 迁移方式（一次一页）

### 2.0 两遍走（2026-09-14 追加）

首页与后台的改动量比登录页大一个数量级，所以拆成两遍，**颜色与取值分开落地**：

- **pass 1（颜色）**：变量改名到统一语义名 + 硬编码颜色换成令牌。每个替换后的取值与替换前
  **完全相同**（强调色透明度统一用 `color-mix(in srgb, var(--accent) N%, transparent)`，
  用的正是 accent 原 rgb），所以 pass 1 结束应当**看不出任何视觉差异**。
- **pass 2（取值）**：间距 / 字号 / 圆角 / 画布的取值按 §1.3–§1.5 与 §3 收敛 ——
  这一遍**会**看出变化，放在登录页目视验收通过之后做。

好处是"改错了"与"改丑了"能被分开归因：pass 1 之后页面若有异常，一定是引用写错了
（静态检查能抓），不会是取值没谈拢。

### 2.1 每页步骤

1. 每页**单独提交**，顺序 `login → index → admin`；两个项目各自独立提交、各自跑测试。
2. 每页只做三件事：① `:root` 补齐统一令牌；② 该页内的硬编码换成 `var(...)`；③ 按 §1.3 / §1.4 映射表收敛间距与字号。
3. **硬边界（不满足就不提交）**：
   - 不改任何 `id` / `class` 名 / 函数名 / DOM 结构 —— 既有静态断言与 3 份 Node 行为断言（login 17 项 / index 20 项 / admin 41 项）必须原样通过；
   - 不引任何外部资源（零 CDN 不变）；
   - 全量 pytest 全绿（当前 项目一 432 / 项目二 634）。
4. 目视验收：每页改完本地起服务看一眼（登录页三屏、工作台空/有会话、后台五个 tab），确认没有塌布局、没有对比度倒挂。

## 4. 明确不做的事

- 不引入 Tailwind / 任何 CSS 框架或预处理器（与"自包含、零 CDN"一致，也避免把样式构建变成新的依赖）。
- 不改布局结构（栅格、断点、DOM 层级）——只统一"值"，不重构"形"。
- 不改字体族（`--mono` 两个项目取值本就不同，属平台差异，保留）。
- 不加动效、不加装饰性渐变、不追求炫酷。
- 不动深色主题的取值（它已达标），只统一变量名。

## 附：这些数字怎么来的

- 颜色字面量 / 变量 / 取值分布：正则扫描 6 个页面的 `<style>` 块（不含 `<script>` 里的内联样式字符串，后者单独统计）。
- 对比度：WCAG 2.1 相对亮度公式 `(L1+0.05)/(L2+0.05)`。
- 每个提案值都标注了"出处"，且都验过对比度（见 §1.1 / §1.2 表格）。
- 结论可复算：审计与对比度都是脚本算出来的，不靠肉眼估计。

### 3.1.1 浅色主题的强调色选型（2026-09-14 晚，脚本实测）

先把决策要用的亮蓝 `#4c8dff` 放到浅色底上量一遍，结果它**在浅色主题里不能用**：

| 候选 | 白底 | p1 画布 `#f4f5f8` | p2 画布 `#eef1f8` | 判定 |
|---|---|---|---|---|
| `#4c8dff`（深色页在用的亮蓝） | 3.20:1 | 2.94:1 | 2.83:1 | **连图形门槛 3:1 都不到** |
| `#3b82f6`（blue-500） | 3.68:1 | 3.37:1 | 3.25:1 | 只够图形/大字 |
| **`#2563eb`（blue-600，采用）** | **5.17:1** | **4.74:1** | **4.57:1** | **正文达标（最浅的达标档）** |
| `#1d4ed8`（blue-700，备选） | 6.70:1 | 6.15:1 | 5.93:1 | 达标，余量更足 |

所以把 `#1d4ed8` 记为备选：**若后续把画布调暗、或要把强调色用到更小的字号上，退一档即可**。
